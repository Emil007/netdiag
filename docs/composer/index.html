netdiag

Build a ready-to-run docker-compose.yml for your home LAN. Everything stays in your browser — nothing is uploaded.

1. Site

A label for reports. Timezone is an IANA name (same as the container TZ).

2. Coordinator probe

The Linux Docker host that runs the analyzer. Find the LAN NIC with ip -br link (examples: eth0, enp3s0, wlan0). Do not list this host’s own IP as a canary.

If yes, add another always-on device on that same switch (not this host). That enables local-switch vs uplink localization on the map.

3. Canaries

Only always-on devices that answer ping (~5–15 total). Not every phone or laptop.

Mesh / AP management IPs

Optional. Management IPs must answer ICMP.

Room / spur groups

Name a spur (e.g. living_room) and 1–2 always-on boxes behind that switch. Attach to gateway unless the spur is on the probe’s own switch.

Wi‑Fi sample canary (optional)

Internet checks

4. Ingest token

Satellites must send the same token. Never leave change-me on a real network.

5. Optional satellites

A second vantage improves “local switch vs uplink vs router.” Wired nearer the router → placement: router. Wi‑Fi laptops should use intermittent so sleep ≠ WIFI_PATH.
